Try it

Each demo sends real requests through Ferry. Under every card: the config rule that does it, the Rust code that runs it, and the design record that explains why.

Round robin

GET /hello goes to a cluster of two backends. Ferry alternates between a and b.

How: config round_robin.rs ADR 0010

Canary split

GET /canary is weighted 90/10: most requests go to a, a few to b.

How: config weighted.rs ADR 0010

Header match

The same path with x-canary: always matches a more specific rule that always picks b.

How: config router.rs ADR 0009

Retries

GET /retry hits a backend that fails half the time. Ferry retries 503s up to twice, so about 7 in 8 succeed.

How: config forward.rs budget.rs ADR 0019

No route

GET /nope matches no route, so Ferry answers 404 itself without touching a backend.

How: router.rs forward.rs ADR 0009

WebSocket

Ferry upgrades /ws and tunnels the connection to an echo backend. It counts as an open connection while it lasts.

How: tunnel.rs ADR 0025 ADR 0037

What happens to one request

The stages every request above went through, in order, with the code that runs each one.

AcceptConnection

Accepts the TCP connection, enforces the connection cap, speaks HTTP/1.1 or HTTP/2.

server.rs
RouteMatch

Finds the route by host, path, method, headers and query.

router.rs
LimitRate limit

A lock-free GCRA limiter answers 429 when the route is over its rate.

ratelimit.rs
RewriteFilters

Header edits, redirects, URL rewrites, X-Forwarded-For and a request ID.

forward.rs
BalancePick a backend

Weighted split, then the cluster's policy over healthy endpoints.

cluster.rs
ForwardSend and retry

Pooled connection to the backend; retries within the retry budget.

pool.rs
ObserveMeasure

Counters and histograms per route and cluster: this dashboard's data.
