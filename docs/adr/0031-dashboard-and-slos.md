# ADR 0031: One Grafana dashboard with the SLOs first, checked in CI

- **Status:** Accepted
- **Date:** 2026-10-13
- **Milestone:** M3

## Context

M3's exit criterion: every SLO in plan §5 can be read from the dashboard. The
SLOs are added latency (p50 < 0.2 ms, p99 < 1 ms at 10k req/s per core), 99.95%
success while backends are healthy, zero dropped requests during reloads and
rolling restarts, and flat memory over a 72-hour soak. A dashboard can drift
from the metrics it queries without anyone noticing.

## Decision

- Ship `deploy/grafana/ferry-dashboard.json` (uid `ferry-overview`),
  generated by `deploy/grafana/generate.py`, with variables for datasource,
  job, listener, route and cluster.
- The first row holds the SLOs, with thresholds at the SLO values: added
  latency p50 and p99 (`ferry_request_overhead_seconds`); requests per
  core-second (request rate over `process_cpu_seconds_total`, the "per core"
  in the latency SLO); success ratio (non-5xx share); failed or cut-off
  requests over the range (5xx plus incomplete responses), with a timeline of
  reloads, proxy starts and failures; and resident-memory growth per hour,
  with the RSS series.
- Further rows: RED per route, local replies by reason, gRPC status,
  per-cluster upstream RED, endpoints (healthy, ejected, eligible), panic
  mode, upstream failures, retries and budget, breakers, connections, and
  config (version, time since load, access-log drops, draining).
- `tests/it/dashboard.rs` fails if any query names a metric a running proxy
  does not export, or if the SLO row loses a panel or its threshold.
  `bench/exit/run-m3.sh` evaluates every panel query against a real
  Prometheus scraping Ferry under load.

## Consequences

- "Zero dropped" is shown from Ferry's side: 5xx and cut-off responses next to
  reload and restart markers. A connection refused before Ferry accepts it is
  invisible to Ferry; the load-test exits (M1, M2) remain the proof, and the
  NLB's metrics cover it in production.
- Grafana computes histogram quantiles from buckets, so the latency SLO panels
  have bucket resolution (25–100 µs steps near the targets).
- Alerting rules and runbooks arrive in M5 and should reuse these queries.
